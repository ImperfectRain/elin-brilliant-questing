# Items And Inventory

- `Card.things`, `ThingContainer`, `Chara.Pick(Thing,bool,bool)`, `Chara.DropThing(Thing,int)`, `Card.Destroy()`, `Thing.GetPrice(CurrencyType,bool,PriceType,Chara)`, `Card.Name`, `Card.category`, and `Card.uid` exist (`VERIFIED-METADATA`).
- Runtime capability probe enumerated 33 PC inventory items (`VERIFIED-RUNTIME`).
- BQ now reads made-quality through `Card.GetTotalQuality(true)` when available, falling back only to `Card.Quality`; `Thing.rarity` is intentionally not a quality fallback. Static analysis shows rarity is not crafted quality: `GetTotalQuality(bool includeQuality)` combines `5 + LV + material.quality` and, when requested, multiplies by `Card.Quality`; `ChangeRarity` only changes rarity (`VERIFIED-RUNTIME`, `SOURCE-OBSERVED`, `STUB-VERIFIED`).
- `Chara.Pick(Thing,bool,bool)` is the vanilla high-level transfer path. It finds a destination stack/container, may call `Thing.TryStackTo(destination)` and return the destination stack, or calls `Card.AddThing` (`SOURCE-OBSERVED`). BQ now captures the returned `Thing` and updates its binding if the original uid stacks away; nonzero transfer and persistence remain disposable-save runtime probes.
- `Card.Destroy()` removes a card from its parent, destroys contained things, clears global/party registration for charas, and sets `isDestroyed`; `Card.RemoveThing` removes from held/hotbar/equipment/container before clearing parent (`SOURCE-OBSERVED`). BQ uses the high-level `Destroy()` path and verifies by readback. Destructive live mutation and save/load persistence remain disposable-save runtime probes.
- SourceData `SourceThing.csv` is indexed locally; compact mappings should use row ids, category, value, LV, quality, recipeKey, components, tags, and details only as needed (`SOURCE-DATA`).
