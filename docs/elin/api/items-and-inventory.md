# Items And Inventory

- `Card.things`, `ThingContainer`, `Chara.Pick(Thing,bool,bool)`, `Chara.DropThing(Thing,int)`, `Card.Destroy()`, `Thing.GetPrice(CurrencyType,bool,PriceType,Chara)`, `Card.Name`, `Card.category`, and `Card.uid` exist (`VERIFIED-METADATA`).
- Runtime capability probe enumerated 33 PC inventory items (`VERIFIED-RUNTIME`).
- Runtime selected `Thing.rarity` from BQ's candidate list as readable, but static analysis shows that rarity is not crafted quality. `Card.GetTotalQuality(bool includeQuality)` combines `5 + LV + material.quality` and, when requested, multiplies by `Card.Quality`; `ChangeRarity` only changes rarity (`VERIFIED-RUNTIME`, `SOURCE-OBSERVED`). BQ production-quality checks should not use `rarity` as the made-quality metric.
- `Chara.Pick(Thing,bool,bool)` is the vanilla high-level transfer path. It finds a destination stack/container, may call `Thing.TryStackTo(destination)` and return the destination stack, or calls `Card.AddThing` (`SOURCE-OBSERVED`). BQ must not assume the original thing uid survives stack merge.
- `Card.Destroy()` removes a card from its parent, destroys contained things, clears global/party registration for charas, and sets `isDestroyed`; `Card.RemoveThing` removes from held/hotbar/equipment/container before clearing parent (`SOURCE-OBSERVED`). Destructive live mutation and save/load persistence remain disposable-save runtime probes.
- SourceData `SourceThing.csv` is indexed locally; compact mappings should use row ids, category, value, LV, quality, recipeKey, components, tags, and details only as needed (`SOURCE-DATA`).
